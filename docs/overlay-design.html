Glaude overlay design

State: Draft 2026-10-28, waiting for your notes

Read this first
  • Goal: one hotkey in a game opens Claude, T3 Code, OpenCode or a terminal in a panel over the game, you look or type, press the hotkey again and you are back in the game. No Alt-Tab.
  • Decided today: standalone app in Glaude, Windows only for now, the app's real window is shown and focused (not a picture of it), in a panel that fills the screen except a 50px margin all round, with the dimmed game showing in that margin.
  • What it is not: it does not draw inside the game (no DirectX hook, no injected code), so it cannot upset anti-cheat and cannot show over true exclusive fullscreen. Section 3 says what that means in practice.
  • To change anything, write in the notes box under it, press Copy my notes, and paste to Claude.

1. What you see

Ctrl+` closes · Ctrl+1-4 switches
› Claude Code · dev-0.3.1 · 2 tasks running Building Glaude 0.3.1 ..................... done 41s Running tests ............................ 118 passed ? Push to GitHub and tag the release? (y/n) › _

Press the hotkey. The game dims to about a quarter of its brightness and a panel fills the screen, leaving a 50px margin on every side where the dimmed game still shows, with your app already running in it. The strip along the top (the rail) names the apps you set up; the one in use is marked in the accent colour. Press the hotkey again or click the dimmed game and the panel goes, focus returns to the game, and the game's mouse lock comes back on its own because it is the foreground window again.

Inside the panel is the app's own window, as it looks normally. Glaude does not restyle it. The rail is the only piece of Glaude you see.

2. How it works

Glaude is a small tray app. It keeps the apps you chose running and parked off-screen, so opening is instant. The overlay is two windows:

  1. The shade. Glaude's own window, borderless and transparent, stretched over the game's monitor, always on top, not in the taskbar. It paints the dim and the rail. A click on the dim closes the overlay.
  2. The app's real window. Glaude moves it from its parked spot to the panel rectangle, puts it above the shade (SetWindowPos with HWND_TOPMOST), and gives it focus so you can type.

On close Glaude remembers which window was in front before it opened (the game), parks the app window again, hides the shade and hands the foreground back to the game. Nothing is injected into the game.

Borrowed from Notifi, which already solved these on Windows: showing a window without stealing focus (show_inactive), parking a webview off-screen (the Island chat's PARKED spot), and letting go of global shortcuts while a page in front needs its keys (give_way / take_back). The Win32 bits are a few dozen lines each and get copied, not shared, so Glaude does not depend on Notifi.

Finding the app's window

Each app is an exe path plus arguments. Glaude starts the process (or attaches to it if it is already running, so Claude in the tray is not started twice), waits for its first top-level window with a title, and keeps that window handle. Electron apps (Claude, T3 Code) spawn helper processes; the main window belongs to the first process, which is the one Glaude started. If the window disappears (you closed the app inside the panel), the rail shows the app greyed and the next open starts it again.

3. Where it works and where it cannot

Game display modeOverlayWhy
Borderless window (most modern games' default)WorksWindows composites every window, so a topmost window shows over the game.
Fullscreen with Fullscreen Optimisations on (the Windows 10/11 default)WorksWindows treats it as a borderless window under the hood.
True exclusive fullscreen (optimisations turned off, or an old engine)Does not showThe game owns the screen; only a hook inside the game could draw there. Steam and Discord do that by injecting code, which is the thing we are avoiding.

When the hotkey is pressed and the foreground window is exclusive fullscreen, Glaude cannot tell for sure from outside, so it does the next best thing: it still switches focus to the app (a plain app switch, like Alt-Tab), and the settings page explains how to set the game to Borderless. Honest limit, stated once.

Games that fight for the foreground (some anti-cheat titles call for focus every frame) will pull focus back off the panel. Glaude does not fight back. If this turns out common, the peek mode in the idea map (a live picture of the app, no focus change) is the answer.

4. Apps and the rail

Presets you can turn on with one click, each checked against your machine when added:

PresetWhat Glaude runs
ClaudeThe Claude desktop app exe found in the usual install folder
T3 CodeThe T3 Code exe
OpenCodeYour default terminal running opencode
TerminalWindows Terminal (or the terminal exe you choose)
Any programAn exe you pick, with arguments

One app set up: the hotkey opens it and the rail is hidden. Two or more: the rail shows them in your order, the hotkey opens the one you used last, Ctrl+1 to Ctrl+9 or a click switches. Every app gets the same panel: the game's monitor minus 50px on each side, measured in Windows display-scaled pixels so it looks the same at 1080p and 4K. The rail takes the top 40px of the panel; the app fills the rest.

5. Keys

  • Open and close: Ctrl+` by default (the drop-down terminal convention), rebindable in Settings. Not Shift+Tab: Steam owns it, and Claude Code uses it to change mode.
  • Esc does not close the overlay. Claude Code and OpenCode use Esc to stop a reply. Close is the hotkey or a click on the dim.
  • Switch app: Ctrl+1 to Ctrl+9 while open, also rebindable.
  • Everything else goes straight to the app. Glaude registers only its own two shortcuts and lets go of the switch keys when the overlay is closed, so a game that uses Ctrl+1 still gets it.

6. Look

One ground, one ink, one accent. The shade is near-black (#0b0d10) at 72% over the game. The rail is a plain strip, 40px, app names as text, the active one underlined in teal (#2fbfa8, the only accent colour anywhere in Glaude). Fade in 120ms, fade out 100ms, no slide, no glow, no blur. The Settings page uses the same three tones, dense layout, form lines. One typeface, Segoe UI.

Follows the design bank's rules for the dark style you have approved before: no gradients, no shadows, no uppercase letter-spaced labels, teal as the sole accent.

7. Settings page

Every option in-app, applied live, saved on change. Opened from the tray icon.

  • Hotkey and switch keys, rebindable by pressing them.
  • Apps: add preset or any exe, arguments, order, panel size, remove.
  • Dim level (slider) and animation on/off.
  • Start Glaude with Windows. Start the apps when Glaude starts, or on first open.
  • Check for updates button with release notes shown as Markdown; updates come from GitHub releases, checked at start and every few hours, downloaded in the background, installed on click or on quit.
  • About: version, licence, the standard disclaimer.

8. Stack

Tauri 2 + Rust + Svelte, like Notifi, so the patterns carry over. The windows crate for the few Win32 calls (hotkey, window move, foreground, enumerate windows by process). The shade and the rail are one Tauri window; Settings is a second. Updater: tauri-plugin-updater against GitHub releases. Two IntelliJ run configs (Main Run, Dev Run). LICENSE and README disclaimer from the template. Repo on a dev-0.1.0 branch, plain tags for releases.

9. Milestones

Milestone 1 "Proof"

  • Tray app; hotkey shows and hides the shade over a borderless game, focus returns to the game.
  • One app (Windows Terminal) parked, shown in the panel, focused, parked again.
  • Settings: hotkey, one app, dim level.
  • Check: open Terminal over a borderless game 20 times in a row, type a command each time, no focus left on the wrong window, no visible flicker.

Milestone 2 "Pick your app"

  • Several apps, the rail, switch keys.
  • Presets for Claude, T3 Code, OpenCode; attach to an already running app.
  • Updater, release notes, About with disclaimer, run configs, first release 0.1.0.

Idea map (not now)

  • Peek mode: a live DWM thumbnail of the app with no focus change, for a glance while a cutscene plays. Notifi has the thumbnail code.
  • A dot on the rail when an agent finishes a task, fed by Notifi's agent watchers.
  • Controller: hold the Guide button to open.
  • Side-panel layout; margin size as a setting; per-game profiles; Linux (Wayland layer-shell is a different design).

10. Questions for you

  1. Default hotkey? Claude recommends Ctrl+`: free in games and in all four apps.
  2. Dim level? Claude recommends 72%: the game stays readable as context, the panel stands out.
  3. Should the apps start when Glaude starts, or on first open? Claude recommends on first open: nothing runs you did not ask for, and the one-off wait is a second or two.
  4. Is "Glaude" the shipped name? Fine as a repo name; if it ships, the About page needs it spelt out once.
