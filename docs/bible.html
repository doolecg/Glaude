1. What it is

Glaude is a small Windows tray app. You press one hotkey while playing a game (default Ctrl+`) and an AI coding app opens in a panel over the dimmed game. Press the hotkey again and you are back in the game, with no Alt-Tab. The first app is Windows Terminal; later milestones add Claude, T3 Code, OpenCode and any program you choose.

It shows the app's real window, focused so you can type. It does not draw inside the game: no DirectX hook, no injected code. That keeps it safe with anti-cheat, and it means it cannot show over true exclusive fullscreen. It is for Windows only for now, and for one person's own use first. The full design is in docs/overlay-design.html.

2. Pillars

Every feature must serve at least one.

  1. One key in, one key out. Going from game to app and back is a single hotkey and focus returns to the game on its own. A feature that adds a step to that loop does not belong.
  2. Leave the game alone. Nothing is injected or hooked, so anti-cheat has nothing to object to. We state the limits (no exclusive fullscreen) instead of working around them.
  3. The app stays as it is. Glaude shows the app's own window and does not restyle it. The only Glaude pieces on screen are the dim and, from milestone 2, the rail.
  4. Quiet and lean. It runs nothing you did not ask for, registers only its own shortcuts and keeps little state. Apps start on first open, not at launch.

5. How a milestone runs

  1. Start: Claude writes docs/milestone-N-guide.html (goal, parts, out of scope) and asks doolecg every question it needs in one bundle.
  2. doolecg approves the guide. Claude marks it "In progress: approved" with the date here and in CLAUDE.md.
  3. Claude builds in small steps. After each step, its test steps go in the guide.
  4. End: one review checklist in the guide for doolecg. Fixes from it jump the queue.
  5. Close: Claude marks it done here and in CLAUDE.md, ticks its items in section 4, updates docs/systems.md, records decisions in section 3 and docs/design.md, and adds a line to section 8.

6. Where ideas go

  • Fits a planned milestone: add it to that milestone in section 7.
  • Needs something not built yet: park it under the milestone that builds that thing.
  • Serves no pillar: park it under "Maybe never" with one line on why.
  • Changes a settled decision: ask doolecg; it is not decided until they say so.
  • Never slip it into the milestone in progress, however small.
